# usage-pace

A Claude Code plugin that adds a row above the prompt comparing your weekly usage to a straight-line pace toward the limit reset.

```
Claude ───────────┃────  57%/73% · ↻1d 20h
Codex  ───────────────┃  73%/95% · ↻8h
```

Each row shows:

- a bar of how much of the weekly limit you have used, with a tick marking where an even pace would put you right now
- `used% / pace%`: the share of the limit used so far, against the share you would have used if you spent it evenly across the week
- `↻`: time left until the limit resets

Beyond the usage rows it also lists:

- the Claude sub-agents currently running, with model, elapsed time and last tool used
- Codex jobs started from this session (via the Codex plugin) that are still queued or running

## Layout

```
.claude-plugin/plugin.json   plugin manifest
hooks/hooks.json             registers the module
hooks/register.tsx           state atoms, timers and rendering
hooks/pace.ts                pace maths, bar and colour
hooks/agents.ts              running-agent rows
hooks/codex.ts               Codex weekly limit and job rows
hooks/*.test.ts(x)           tests
types/index.d.ts             plugin state typings
```

`.claude-plugin/types/` holds type stubs generated by Claude Code and is git-ignored; your install regenerates it.

## Install

Clone the repo somewhere Claude Code can load plugins from, for example:

```bash
git clone <this-repo-url> ~/.claude/my-plugins/usage-pace
```

Then enable it the same way you enable any local plugin in your Claude Code setup.

## Codex

The Codex row is optional and read-only. The weekly limit comes from the newest rollout files under `$CODEX_HOME/sessions` (default `~/.codex`), and running jobs come from the Codex plugin's `state.json` files under `$CLAUDE_CONFIG_DIR/plugins/data/codex-openai-codex/state` (default `~/.claude/...`). The row only shows once a Codex limit reading has been found.

## Development

The code is TypeScript with JSX rendered through the Claude Code plugin host. Tests sit beside the source in `hooks/` and import from `claude-code/testing`, so they run under the host's plugin test runner rather than a standalone one.
